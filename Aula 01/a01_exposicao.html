Antes de organizar qualquer prateleira do almoxarifado, você precisa saber o que vai guardar ali. Hoje guardamos a primeira ferramenta: a engenharia de requisitos.

O problema do cliente

Dois problemas opostos, um só sistema

Falta de produtoRuptura de estoque nos momentos críticos da produção — para a fábrica.
Excesso de produtoCusto de armazenagem alto e risco de obsolescência das ferramentas.
Zero rastreabilidadeNinguém sabe quem mexeu no estoque, nem quando — sem histórico.
Conceito

Requisito Funcional × Não Funcional

Funcional (RF)

  • Responde: "o que o sistema faz?"
  • Ex.: permitir cadastrar produto
  • É a nossa Entrega 1 de hoje

Não Funcional (RNF)

  • Responde: "como o sistema se comporta?"
  • Ex.: responder em até 2s
  • Aparece na Entrega 9 (infraestrutura)
Anatomia

Como escrever um bom RF

// ruim — não é testável
"Sistema de login."

// bom — atômico, verificável, rastreável
RF-04 — O sistema deve permitir que o usuário se autentique informando login e senha.
Estrutura do projeto

4 blocos de requisitos — clique para ver

Autenticação
Login, logout, tratamento de erro de autenticação. (Aula 4)
Estrutura/Navegação
Tela principal, nome do usuário logado, acesso às demais telas. (Aula 5)
Cadastro de produto
Listar, buscar, inserir, editar, excluir, validar. (Aulas 6–7)
Gestão de estoque
Listar ordenado, movimentar entrada/saída, alerta de mínimo. (Aulas 8–9)
